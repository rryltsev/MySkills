# Вязкость оксидов. Воспроизведение на CPU

Здесь собраны все 11 исследовательских скриптов из `Viscosity/scripts`, функция межпубликационного взвешивания и автономная проверка численной части. С их помощью можно повторить три вычисления: опубликованный прогноз GPVisc, сравнение классических моделей на исходном тесте и перенос на полностью отложенные составы работы Iida. Входные измерения и контрольные точки модели пользователь получает отдельно.

## Подготовить два окружения

Начните в **`methods/projects`**, на один уровень выше этого README. Команды ниже запускают файлы как программы, чтобы их соседние импорты разрешались одинаково на Windows, Linux и macOS. Сохраните исходную структуру каталогов. Для повторного опыта удобно скопировать `oxide` в новый рабочий каталог и перейти в его родительский каталог. Результаты записываются в `results/` рядом с `oxide/`. Повторный прогон в том же каталоге заменяет одноимённые результаты.

Ниже используются PowerShell и Python 3.11. В Linux/macOS создайте окружения через `python3 -m venv`; замените вызовы `& $bm` и `& $gp` на `.venv-benchmark/bin/python` и `.venv-gpvisc/bin/python`. Подставляйте свои пути к данным. Зафиксированные версии относятся к версии GPVisc v0.3.4 и выделены в отдельные окружения, поскольку общий практикум GFA использует NumPy 2.

```powershell
python -m venv .venv-benchmark
python -m venv .venv-gpvisc
$bm = '.venv-benchmark/Scripts/python.exe'
$gp = '.venv-gpvisc/Scripts/python.exe'
& $bm -m pip install -r oxide/requirements-benchmark.txt
& $gp -m pip install -r oxide/requirements-gpvisc.txt
& $bm oxide/check_numerics.py
```

Последняя команда проверяет матрицу ядра и неопределённость на одном искусственном индуцирующем центре, сохранение двух совпадающих измерений с неоднозначным источником и линейный контроль с известными ответами 2,75 и 2,25. Она работает без релиза, весов или экспериментальной базы.

## Получить входы и записать их происхождение

- Распакуйте релиз v0.3.4 `charlesll/gpvisc`. Переменная `$release` должна указывать на каталог, содержащий одновременно `src/gpvisc/models/GP_model1`, `GP_model2`, `GP_model3` внутри той же папки моделей и `code_paper_EPSL/additional_data/all_viscosity.hdf5`. Для сверки с исходным API также используется код релиза `src/gpvisc`. Запишите версию, хеш архива и хеш HDF5. [Зафиксированный релиз GPVisc](https://zenodo.org/records/14673467)
- Для аудита отдельных первичных источников и опыта Iida дополнительно нужен архив GPVisc с таблицами `gpvisc_database_lp.csv`, `gpvisc_database_hp.csv`, `gpvisc_database_references.csv` в корне ZIP. Он содержит измерения, температуру, давление и ссылки на публикации. Переменная `$curated` обозначает путь к этому отдельному файлу. Остальные стадии можно выполнить по релизу. [Описание базы](https://doi.org/10.18715/IPGP.2024.lycv4gsa)

```powershell
$release = '/path/to/charlesll-gpvisc-5dbe6cc'
$hdf = Join-Path $release 'code_paper_EPSL/additional_data/all_viscosity.hdf5'
$curated = '/path/to/gpvisc_database.zip'
```

## Пройти от входов до пользовательского прогноза

| Этап | Команда PowerShell из родительского каталога `oxide` | Результат и смысл |
|---|---|---|
| 1. Аудит | `& $bm oxide/audit_dataset.py $curated --hdf $hdf` | `dataset_audit.json` и `test_curated_sources.csv`. Сверяются состав, T, P, y, кратность, возможные источники и пересечение групп |
| 2. GP | `& $gp oxide/reproduce_gpvisc.py --release $release --out results` | `gpvisc_posterior.npz`, `gpvisc_predictions.csv` и `gpvisc_metrics.csv`. Состав и порядок обучающих тензоров сверяются с HDF5 |
| 3. Сверка GP | `& $gp oxide/verify_gpvisc.py --release $release --posterior results/gpvisc_posterior.npz --sample-size 64` | `gpvisc_native_check.json`: максимальные и среднеквадратичные отклонения среднего GP1, сероящичной сети и прогнозного SD от исходного API. Для полного теста опустите `--sample-size` |
| 4. Классические контроли | `foreach ($m in 'lr','xgb','ann','svr') { & $bm oxide/classical_benchmarks.py $hdf $m }` | Файлы `results/classical/*.json` с RMSE, медианной абсолютной ошибкой и R². Для начала достаточно `lr` |
| 5. Выбор кривой | `& $bm oxide/composition_curve.py select $hdf` | `composition_curve_validation.json` фиксирует выбор гиперпараметров по validation |
| 6. Экспорт кривой | `& $bm oxide/composition_curve.py evaluate $hdf` | Модель заново обучается на train + valid с зафиксированным выбором. Записываются `composition_curve_model.npz`, прогнозы на test и метрики |
| 7. Сопоставление | `& $bm oxide/compare_models.py $hdf` | `comparison.json` и `test_comparison.csv`. Сверяются ID строк и цели. Для переноса ошибки на ансамбль учитываются группы составов |
| 8. Проверка конечной команды | `& $bm oxide/verify_inference.py $hdf` | `inference_checks.json`: сохранённый тест воспроизводится через CSV, сверяются массовый и молярный базисы, вычисляется чувствительность к +1 K |
| 9. Рисунок | `& $bm oxide/plot_benchmark.py` | `benchmark.png` по таблице и метрикам этапа 7 |
| 10. Независимый состав | `& $bm oxide/iida_transfer.py $curated --hdf $hdf` | В `results/iida_transfer/` сохраняются прогнозы, статистика исключения групп, расстояния до оставшихся составов и сравнение с линейным контролем |

В историческом воспроизведении таблицы из статьи базовые модели учатся на объединении исходных train + valid. Из этого нельзя заключить, что можно выбирать гиперпараметры по test. В ветви `composition_curve` выбор проходит на предписанной валидации до финального переобучения. На этапе 10 из обеих частей исключаются все группы, связанные с отложенным источником, и точные совпадения нормированных составов при любой T и P. Отчёт дополнительно показывает близкие составы, возможные даже после удаления точных совпадений.

### Почему нужен отдельный экспорт GP

В ядре Матерна используются индуцирующие точки. Экспортёр блоками собирает поправку к ковариации, учитывает диагональную поправку и шум измерения, выполняет разложения Холецкого и сохраняет коэффициенты среднего. Для GP1 он также сохраняет факторы, необходимые для прогнозной дисперсии. Сверяйте отдельно прогноз вязкости, сероящичный член и стандартное отклонение. Совпадение одной средней величины не проверяет дисперсию. Скрипт нативной сверки печатает расхождения; допустимый порог определяют единицы и требуемая точность.

### Свой CSV

Создайте `mixture.csv` с заголовком `id,T_K,P_GPa,SiO2,CaO` и одной строкой `mix,1700,0,60.0843,56.0774`. После этапов 2 и 6 выполните

```powershell
& $bm oxide/predict_viscosity.py mixture.csv --basis wt
```

Две навески отвечают одному молю каждого оксида. При `--basis mol` замените последние два поля числами `1,1`. Вы получите совпадающие прогнозы GP1, среднего трёх GP, температурной кривой и их ансамбля. Предпоследняя колонка выдаёт `log10(η / (Па·с))`, последняя — `η` в Па·с. Неизвестное имя оксида вызывает ошибку ввода. Оцените применимость по составу, давлению, температуре и положению относительно ликвидуса прежде, чем интерпретировать прогноз.
