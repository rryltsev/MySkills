# Практикум по исследовательским проектам

В шести занятиях вы проверите научные алгоритмы на данных, для которых ответ можно рассчитать вручную. Каждый пример запускается на CPU за секунды после установки зависимостей. Для полного практикума достаточно Python 3.11. Веса MLIP, траектории, закрытые контрольные выборки и доступ к кластеру для занятий не требуются.

## Подготовка

Откройте каталог `methods/projects` в терминале. В Windows PowerShell выполните

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python practice.py all
.venv/Scripts/python -m pytest -q tests
```

В Linux и macOS

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python practice.py all
.venv/bin/python -m pytest -q tests
```

Ожидайте шесть блоков результатов и 31 пройденный тест. Можно передать `practice.py` имя одного занятия. Проверка архива выполнена с NumPy 2.4.6, SciPy 1.17.1, ASE 3.29.0 и pytest 9.2.0. Для изменения упражнений используйте отдельную рабочую копию. Первичное происхождение и контрольные суммы исследовательского кода приведены в [карте исходников](SOURCES.md).

| Занятие | Самостоятельное действие | Результат для сверки |
|---|---|---|
| `motifs` | Измерить длительность структурного мотива | Один полный эпизод, один цензурированный справа, RMST = 0,5 пс |
| `viscosity` | Пересчитать массу оксидов в моли и перенести температурную кривую | 0,5 SiO₂ + 0,5 CaO, прогнозы 0,967 и 0,300 в десятичном логарифме |
| `formulas` | Отсеять сингулярность, выбрать формулу с учётом сложности | На контрольных точках 7 и 8, решение one-SE выбирает `short` |
| `elasticity` | Восстановить гессиан свободной энергии | 73 состояния, модули Хилла 100 и 60 ГПа |
| `geometry` | Различить ошибку состава и ошибку сдвига | 56/80 узлов дают 70 % точно, измеренный сдвиг 0,012 |
| `parity` | Сравнить E/F/S на двух вычислителях | Расхождение 0,00005 эВ/атом при совпадающих силах и напряжениях |

## 1. GFA. Структура, динамика и время жизни мотива

**Вопрос.** Более частый мотив может жить дольше или просто чаще образовываться. Для различения нужны атомные идентификаторы, известный интервал сохранения кадров и временной ряд принадлежности мотиву для каждого атома.

1. Начните с равновесного участка и независимых реплик. Проверьте температуру, давление и признаки диффузии. Сохраните состав, плотность, PBC, шаг записи и систему единиц. Для MSD и собственной промежуточной функции рассеяния используйте развёрнутые координаты и вычтите дрейф центра масс.
2. Постройте соседский граф с учётом периодических образов. Назовите радиус и способ его выбора, например минимум частичной RDF. В `descriptors.py` и `structural_atlas.py` есть локальные признаки, общие соседи, связные компоненты, классификация и перемешивание меток внутри химических видов. Такой контроль сохраняет численность каждого вида и позволяет проверить, превышает ли кластеризация случайную.
3. Сформируйте булеву матрицу «кадр × постоянный ID атома». Сумма по атомам даёт населённость. Для длительности исключите эпизоды, начавшиеся до первого кадра. У эпизодов, дошедших до последнего кадра, известно лишь минимальное время жизни. Сравните кривую Каплана — Мейера и площадь под ней до фиксированного горизонта RMST. Если конец кривой не поддержан наблюдениями, модуль возвращает интервал. Исторические имена полей `RMST_2ps` относятся к горизонту по умолчанию 2 пс.
4. Посчитайте непрерывную сохранность пары соседей и вероятность повторной встречи той же пары. У них разная чувствительность к кратким выходам за порог. В `neighbor_dynamics.py` есть гистерезис и несколько начальных моментов. Интервалы по репликам оценивайте на уровне независимых траекторий.
5. Для границы кристалл–жидкость обучите критерий порядка на контролях обеих фаз, проверьте его на перемешанном составе, найдите фронты с учётом периодической оси. В `interface_screening.py` и `interface_series.py` стационарность проверяется по температуре и шести компонентам давления. Укажите правило обрезки времени, шаг сохранения и диапазон пространственного усреднения.

**Попробуйте.** Запустите `practice.py motifs`. У первого атома мотив уже присутствует в начале окна. У второго наблюдается полный эпизод, у третьего теряется конец. Попросите Codex изменить окно так, чтобы последний остающийся эпизод оказался цензурирован. При наличии ненулевого хвоста интервал RMST расширится. Для примера со сдвигом всей ячейки запустите `python -m pytest -q tests/test_neighbor_dynamics.py`.

**Запрос к Codex.** «В [пакете gfa](gfa) найди расчёт MSD, времени первого пересечения уровня 1/e и длительности эпизода. Нарисуй три измерения на одной короткой искусственной траектории. Покажи единицы, нулевую гипотезу, вклад первого и последнего кадра и результат при удвоенном шаге записи».

## 2. Оксидные расплавы. Вязкость, состав и перенос на другую публикацию

**Вопрос.** Сможет ли модель предсказать температурную зависимость вязкости для нового состава? Измерения одного состава при разных температурах могут создать завышенную оценку точности при случайном разделении строк.

1. Явно задайте входной базис: массовые проценты или молярные доли оксидных формульных единиц. Для массового базиса разделите массу каждого оксида на его молярную массу, затем нормируйте по сумме молей. Разные формы окисления железа учитываются отдельными компонентами. Выберите порядок столбцов по именам модели. Входы требуют температуру в K и давление в ГПа. Цель — `log10(η / (Па·с))`.
2. При воспроизведении GPVisc сопоставляйте записи по нормированному составу, температуре, давлению и измеренной вязкости с сохранением кратности дубликатов. Для воспроизведения статьи сохраняйте её индексы. Для проверки на новом составе отделите все температуры этого состава. Для проверки внешнего переноса зарезервируйте публикацию целиком и проверьте пересечение составов с обучением.
3. В [модуле кривых](oxide/composition_curve.py) есть дескрипторы состава и давления, выбор центров методом наиболее далёкой точки, гладкий температурный член и локальная поправка. Начните с простой температурной ветви, выберите гиперпараметры на валидации и зафиксируйте их до теста. Отдельно приведите RMSE в dex, среднюю и медианную абсолютную ошибки, число точек и число составов. Ошибка 0,3 dex соответствует приблизительно двукратной ошибке вязкости.
4. При переносе на шлаки разделите измерения при температуре выше ликвидуса и в области возможной двухфазности. Проверьте влияние формы Fe и неопределённости состава на результат. Укажите источник ликвидуса. Чтобы одна длинная температурная серия не определяла итог, рассчитайте также средний показатель с равными весами рецептур или источников.

**Попробуйте.** `practice.py viscosity` учится на восьми искусственных измерениях при двух составах и проверяет две новые температуры. Затем измените температурную функцию только для второго состава. Попросите Codex провести проверки «новая температура знакомого состава» и «новый состав» и объяснить разницу. Для исторического CLI `composition_curve.py` операции `select` и `evaluate` требуют исходный HDF5 с опубликованными разбиениями, пакет h5py и запись результатов в каталог `results` относительно модуля. Практикум вызывает численные функции напрямую.

**Запрос к Codex.** «Аудируй мою таблицу по источнику, составу, температуре, давлению и единицам вязкости. Составь перечень неоднозначных строк. Заморозь список внешних составов и сравни ошибку по строкам и с равным весом составов».

Полное воспроизведение на CPU включает экспорт трёх GP, сверку с исходным API, четыре классические модели, повтор пользовательского прогноза и подборку Iida, отложенную целиком. [Окружения, входы и десять команд](oxide/README.md)

### Опыт переноса на конвертерные шлаки

В проекте BOF сначала отделили горячие серии, пригодные для сравнения жидких расплавов, и описали допущение о степени окисления железа. Для локальных кандидатов использовали аррениусовскую регрессию и поправку к корреляции Iida. При выборе кандидата исключали целую публикацию и оценивали ошибку по работам Wang и Kim–Park, для которых проверяли пересечение с архивом. Данные Shen ранее входили в архив GPVisc, поэтому их использовали как отдельную проверку чувствительности. Окончательному сравнению на Kovtun предшествовала фиксация модели. Исходные затруднения на Kovtun уже были известны авторам опыта, и это важно отметить при интерпретации внешней оценки.

При подгонке каждая работа получила равный суммарный вес. Внутри работы поровну взвешивали рецептуры, внутри рецептуры — температуры. В практикуме три температуры единственного состава из работы A получают вес 1/6 каждая, одно измерение из работы B — вес 1/2. В своей проверке выведите ошибку на жидкой ветви выше ликвидуса и отдельно для всех измерений, число составов и оценку при альтернативной доле Fe³⁺. [Исходная реализация весов](oxide/study_weights.py)

## 3. Символьная регрессия. Формула, область определения и слепая проверка

**Вопрос.** Минимальная ошибка на конечной сетке может принадлежать формуле с полюсом между точками. Проверять нужно как точность, так и математическую допустимость на заявленной области.

1. До подбора зафиксируйте обучающую часть, валидацию, область интерполяции, внутреннюю область без обучающих точек и внешнюю область экстраполяции. Масштабы входов и цели оцените на обучении. Зафиксируйте версии PySR или Operon, грамматику, лимит сложности, вычислительный бюджет и seed.
2. Проект ТПР использует открытую трёхпеременную грамматику [formula_tools.py](symbolic/formula_tools.py). Коллекция ML-Materials использует отдельную двухпеременную грамматику [expressions.py](screening/expressions.py). Числа сложности имеют смысл внутри соответствующего протокола. Передайте открытой утилите `python symbolic/formula_tools.py --expression "x1**2 + x2"`. Ожидаемый вес дерева — 4. При наличии разрешённого CSV можно передать `--data` с колонками `x1,x2,x3,y`. Для экспорта внешних SymPy-выражений из двухпеременного протокола дополнительно нужен SymPy.
3. Сохраните исходную и нормализованную формулы. Например, при сокращении дроби может исчезнуть разрыв исходной функции. Проверяйте обе формы на регулярной сетке и точках Соболя, затем примените интервальное разбиение области. Конечная сетка выявляет наблюдаемый сбой. Статус `unresolved` у интервального метода означает, что данный бюджет разбиений не подтвердил корректность. Критерий приёмки должен предусматривать такой исход.
4. Выбирайте модель среди допущенных кандидатов. Реализация [one-SE](screening/selection.py) строит порог как MSE лучшего кандидата плюс стандартная ошибка среднего его поточечных квадратов ошибки на валидации. Среди прошедших этот порог выбирается кандидат меньшей сложности. Эта эвристика предполагает содержательную валидационную выборку и не является тестом статистической значимости. Для зависимых групп потребуется оценка на уровне групп. Сохраните формулу, гиперпараметры, экспорт предсказаний и контрольную сумму до независимой оценки.

**Попробуйте.** В `practice.py formulas` у длинной формулы нормированная MSE равна 0,25, у короткой — 0,36. Разберите четыре наблюдения вручную. Проверьте `1/x1` в окрестности нуля и `1/(1+x1**2)` на той же области. Затем попросите Codex предложить синтетический пример, где выигрыш от длинной формулы превышает порог.

**Запрос к Codex.** «Покажи дерево, сложность и доменные ограничения двух формул. Заморозь правило отбора до теста. Отдельно выведи долю конечных прогнозов и ошибку по каждой из трёх геометрических областей».

### Экспорт дерева Operon и рационализация коэффициентов

Сохраните узлы дерева Operon с типом, значением, арностью, длиной поддерева и соответствием переменных исходным столбцам. У переменной может быть собственный множитель. Порядок детей критичен для вычитания и деления. Модуль восстанавливает исходные узлы и строит выражение с полным представлением коэффициентов. В `practice.py formulas` два листа с весом 0,4 дают `0.4*x1 + 0.4*x1`. Сначала сравните прогноз открытого парсера с независимым воспроизведением узлов в Float64. Затем отдельно измерьте отклонение в исходной точности Float32 и, при наличии движка, сопоставьте с его собственным векторным вычислением. Запишите худшую точку, абсолютную и масштабированную ошибки и контрольную сумму артефакта. Повтор в свежем процессе на сохранённых входах подтверждает читаемость экспорта. Синтетический пример здесь проверяет арифметику узлов без запуска Operon. [Функции экспорта и воспроизведения](symbolic/native_tree.py)

**Точное преобразование и подбор.** Двоичное число 0,8 имеет длинное точное рациональное представление. Для вывода короткого десятичного литерала `sympy_string` сверяет его `as_integer_ratio()` с исходной дробью. Приближение малой дробью, например `4/5`, создаёт отдельного кандидата. В историческом пилоте константы дооптимизировали только на train, пробовали одиночные и совместные замены коэффициентов малыми дробями, затем снова проверяли грамматику, область и правило выбора. Порог знаменателя 20 был параметром этого опыта. Сохраните дерево до и после преобразования, причину допуска и протокол сравнения. Для функции `sympy_string` понадобится SymPy.

### Независимое сравнение сети и PySR

В слепом пилоте независимая сессия получала одинаковые открытые train/val/test_x для двух методов. Одна ветвь учила однослойную сеть с сигмоидной скрытой активацией и линейным выходом. Другая запускала свежий PySR на исходных обучающих метках. Сеть не передавала ему прогнозы или найденное решение. При последовательной работе «сначала сеть, затем PySR» обе ветви сохраняют самостоятельность, если одинаковые правила и бюджет зафиксированы заранее.

Заморозьте версию разбиения, отображение ID, код скоров, доменные фильтры, seed и отпечатки окружения. Храните веса сети вместе с нормировщиками, обученными только на train. Оставьте идентификаторы интерполяционной области, внутренней лакуны и экстраполяции у оценщика. Протокол разделяет строки по выданным разбиениям и скрытым областям. Для нескольких реализаций одной физической серии дополнительно закрепите родительский ID за единственным разбиением и проверьте пересечения множеств ID. Перед раскрытием целей создайте контрольные суммы списка моделей и таблиц прогнозов. В свежем процессе проверьте те же прогнозы из весов NPZ и из сохранённого AST. Учебный пример сети с нулевым входом даёт 0,5. [Исходная функция воспроизведения сети](screening/nn_replay.py)

## 4. CoCrNi. Упругость, дефекты, химический порядок и QHA

**Вопрос.** Как разложить расхождение с эталоном на вклад геометрии, метода конечных разностей, температуры и потенциала?

1. Для сравнения моделей возьмите одну структуру с одним распределением видов, одним объёмом, одинаковыми граничными условиями и порядком атомов. Сначала убедитесь в согласованных энергии, силах и напряжениях. Определите начало энергии и покажите сырой результат рядом с возможной поправкой по элементам, определённой на обучающей части. Функция `matched_errors` и её тест внутри [gfa](gfa/model_comparison.py) демонстрируют восстановление порядка после сортировки входа VASP.
2. Для EOS вычислите энергию на нескольких объёмах вокруг минимума. Рассмотрите остатки подгонки и положение минимума относительно сетки. Для статической упругости подготовьте парные положительные и отрицательные деформации, уточните, какие внутренние координаты релаксировали, проверьте чувствительность к амплитуде. Сохраните необработанный тензор перед симметризацией и проверьте положительность собственных значений.
3. Для QHA постройте Helmholtz `F(V,η,T) = E_static + F_ph` с указанным учётом нулевых колебаний. Проверьте нормировку на ячейку, сетку q, величину смещений и устойчивость фононов. Определите `Veq(T)` внутри сетки по объёму, вычислите гессиан по шести компонентам деформации и разделите его на равновесный объём. Для `F` в эВ и объёма в Å³ множитель перевода в ГПа равен приблизительно 160,21766. Усреднение Фойгта, Рейсса и Хилла даёт макроскопические оценки. Подпишите изотермические модули и укажите ансамбль и химическую конфигурацию.
4. Для энергии вакансии в чистом элементе при одной опорной геометрии используйте `E(N−1) − (N−1) E(N)/N`. Для поверхностей считайте `(Eslab−Nμ)/(2A)` и проверяйте вакуум, обе терминации и толщину. Для дефекта упаковки зафиксируйте площадь, число плоскостей сдвига, нулевую геометрию, ограничения релаксации и сетку смещений. Для границ зёрен нужны конкретные бикристаллы и варианты относительной трансляции.
5. Для химического ближнего порядка проверьте вероятности пар на случайной конфигурации, сохранение состава при обменах, обратимость предложений и статистику принятия Монте-Карло. Раздельно проанализируйте изменение SRO, упругости и энергии дефекта. Сравнение разных температур на разных случайных реализациях смешивает несколько источников разброса.

**Попробуйте.** В `practice.py elasticity` гессиан квадратичной энергии восстанавливается из одной нулевой точки, 12 однокомпонентных и 60 смешанных деформаций. При изотропном тензоре оценки Фойгта и Рейсса совпадают. Сделайте одну диагональную компоненту отрицательной и проверьте, как изменился признак `stable`. [Модуль QHA](elastic/qha_core.py)

### Магнитные состояния и отбор структур для проверки SRO

В плане опыта Prophet-Spin равновесный химический порядок сопоставляли с магнитными окружениями. Для локального обмена Co/Cr/Ni сравнивайте полную `ΔE` одного предложения с `kBT`. Нормирование на атом скрывает стоимость локального хода при увеличении ячейки. Для свободного спин-поляризованного DFT сохраняйте сошедшиеся локальные моменты **после SCF**. Начальная `MAGMOM` описывает старт. Для цены предписанного переворота требуются контролируемые моменты либо проверенные метастабильные состояния. Сравните две цепи на одной решётке — с замороженным и с перестраивающимся спином. Проверьте симметрию глобального переворота в нулевом поле, обратимость ходов, независимость от старта, видовые корреляции моментов и Уоррена–Каули по оболочкам. Эти пункты описывают дизайн проверки и требуют измерения на конкретной модели.

Для отбора конфигураций в отдельном опыте CoCrNi задавали квоты сразу по химии и структурному классу. Проверьте вместимость каждой ячейки «состав × класс», решите целочисленное распределение квот, проведите FPS в исходном многомерном SOAP-пространстве внутри каждой ячейки обучения. Зафиксируйте стартовую структуру и политику равных расстояний. Затем посчитайте расстояния до ближайшего выбранного представителя раздельно на train, validation и test, сохраняя отложенные наборы только для аудита. Окраска UMAP иллюстрирует выбор. Количественное покрытие оценивается в исходном пространстве. Метка «разупорядоченный» по CNA требует независимого динамического критерия для классификации жидкости.

## 5. Ti–Al–X. Аудит генератора геометрий до разметки DFT

**Вопрос.** Как установить, что обозначение кандидата соответствует тому, что фактически записано в POSCAR, ещё до расходования вычислительного времени?

1. Для замещений выпишите число доступных узлов каждой подрешётки и требуемые целые количества видов. Проверьте сумму по подрешётке и результирующий химический состав всей ячейки. Если номинальная доля недостижима, явно укажите ближайшую реализуемую композицию и согласуйте допуск либо измените размер ячейки. При различных номинальных точках проверьте дубли фактических заселённостей.
2. Для деформации задайте систему координат и порядок компонент. В соглашении ASE векторы ячейки записаны строками. Для декартова градиента `F` получается `cell_new = cell @ F.T`. Восстановите фактический градиент из записанной новой ячейки и проверьте `(F.T @ F − I)/2`. Для инженерного сдвига `γxy = 2 εxy`. Наклонная ячейка обнаруживает ошибки соглашений, которые легко пропустить на кубе.
3. Для планарного дефекта привяжите сдвиг к физическому вектору, площади и нулевой опоре с тем же электронным и механическим протоколом. Для точечных дефектов проверьте фактические изменённые узлы после симметрии и дубли оболочек. Для жидкости запишите наблюдаемые признаки стадии и температуры. Случайное смещение атомов само по себе недостаточно для присвоения метки равновесной жидкости.
4. Разделите родительские структуры по происхождению до отбора обучения и теста. Связанные деформации, кадры одной траектории и нулевая опора с её сдвигами должны быть прослеживаемы. До расчёта SOAP и FPS сопоставьте число уникальных кандидатов с квотой и проверьте устойчивость к стартовому кандидату. Для повтора храните предыдущие манифесты и атомарно публикуйте новый этап после проверки полноты.

**Попробуйте.** `practice.py geometry` рассчитывает 70 % от 64 и 80 узлов точно как рациональное число. Затем измеряет фактический инженерный сдвиг наклонной ячейки. Попросите Codex заменить правое умножение на левое, вывести полный тензор деформации и найти компоненту с максимальным расхождением.

## 6. Matbench и M3GNet. Численная проверка переноса между CPU и GPU

**Вопрос.** Какие свойства модели доступны и совпадает ли измеряемый ответ на выбранном устройстве?

1. Зафиксируйте карточку модели, назначение выхода E/F/S, контрольные суммы использованных весов и версию рантайма. Сохраните исходную структуру и идентификаторы атомов. Проверьте размещение вычислительных операций на конкретном устройстве. Одной видимости GPU во фреймворке недостаточно для подтверждения исполнения ядра.
2. Выполните одинаковое статическое вычисление на обоих устройствах. Сохраните сырые величины, порядок компонент Войгта либо полный тензор, знак напряжений и единицы. Для нескольких структур сравнивайте каждую с её точной парой. Исторический K40m/M3GNet опыт относится к конкретному оборудованию и программной сборке.
3. [Утилита сравнения](matbench/compare_records.py) принимает два JSON-файла со схемой, показанной в `practice.py parity`. Перед подачей сопоставьте геометрии и порядок атомов по исходникам. Утилита проверяет совпадение числа атомов, отпечатков весов, форм тензоров и конечность значений. Метрики — модуль разности полной энергии на атом, максимум покомпонентных отклонений сил и напряжений. Пороги задавайте из требуемой точности задачи и точности чисел. Тест переноса отвечает на отдельный вопрос от проверки против независимых DFT-меток.

**Попробуйте.** `practice.py parity` сравнивает два искусственных результата. Измените только одну компоненту силы на 0,003 эВ/Å, затем поменяйте отпечаток весов в одном файле. В первом опыте изменится ровно одна метрика, во втором получите ошибку идентичности.
