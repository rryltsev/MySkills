# Как проверить экспорт DPA4

На одном и том же кадре две реализации должны дать согласованные полную энергию, каждую компоненту силы и все шесть компонент напряжения. В проекте MLIP-research аудит выявил ошибку, которую трудно заметить по итоговым графикам. Расчёт успешно создавал экспорт и проверял его, затем снова загружал исходный checkpoint для фононов и метрик. Для воспроизведения важен путь к модели в том процессе, который вычислил конечный результат.

## Упражнение без GPU и сторонних пакетов

Из корня коллекции выполните:

```sh
python methods/deployment/export_check.py demo
```

В поле `equal` все отклонения нулевые. В `perturbed` энергия и силы по-прежнему совпадают, но одна компонента напряжения отличается на 0,000002 эВ/Å³. При учебном допуске 0,000001 поле `passed` принимает значение `false`. Это намеренный отрицательный контроль. Попросите Codex вывести формулу для каждого из трёх отклонений и показать, почему сравнение только гидростатического давления могло бы пропустить ошибку в сдвиговой компоненте.

## На машине с подготовленным DeepMD и GPU

1. Выберите обученный `.pt`, целевой GPU и репрезентативные периодические ячейки. Добавьте неортогональную ячейку, конфигурацию с ненулевыми силами и сдвиговыми напряжениями. Сохраните порядок атомов и кадров в одном файле `frames.extxyz`. Заранее зафиксируйте допустимые ошибки. Ниже показаны значения из одного исторического теста сериализации.
2. В активированном окружении DeepMD запишите версии DeepMD, Torch, драйвера, модель GPU, SHA-256 checkpoint и переменные экспорта. Команда ниже предназначена для Bash на целевой машине. Используйте новый путь вывода.

   ```bash
   DP_TRITON_INFER=2 DP_TF32_INFER=0 DP_AMP_INFER=0 dp --pt freeze -c checkpoint.pt -o frozen.pt2
   ```

3. Запустите два отдельных процесса. Первый нужен для явного эталонного измерения. Второй открывает файл `frozen.pt2`. Из корня MySkills выполните:

   ```sh
   python methods/deployment/export_check.py predict reference checkpoint.pt frames.extxyz ref.json
   python methods/deployment/export_check.py predict export frozen.pt2 frames.extxyz frozen.json
   python methods/deployment/export_check.py compare ref.json frozen.json --energy 1e-5 --forces 2e-4 --stress 1e-6
   ```

4. Сопоставьте хеши из вывода с журналом freeze, сохраните обе записи, входные структуры, версии и допуски. `compare` возвращает 1 при превышении допуска. При успехе передайте именно этот `.pt2` в процесс повторной оценки, фононов или МД. Запишите фактически прочитанный путь и хеш. Сбой экспорта или сравнения требует диагностики. Для LAMMPS нужна отдельная проверка установленного плагина через `run 0`.

Энергия сравнивается в эВ на атом, силы по максимуму абсолютных покомпонентных отклонений в эВ/Å, напряжения в эВ/Å³ с соглашением ASE `xx yy zz yz xz xy` и положительным растяжением. При сравнении с внешним кодом сначала согласуйте знак давления, порядок компонент, единицы и вклад кинетической части. Здесь обе записи статические и сформированы через один интерфейс ASE.

## Как измеряли скорость

В историческом сравнении DPA4-Neo на A100 freeze занял 514 с. Измеряли отдельно загрузку, первый вызов и время после прогрева. Одинаковые последовательности слегка возмущённых структур подавали в отдельные процессы, обходили кэш результатов ASE и синхронизировали GPU перед каждым отсчётом и после него. Для четырёх размеров 96–864 атома отношение установившегося времени исходного checkpoint к Triton 2 составило 2,78–4,56. Это измерение задержки полного вызова ASE на конкретной машине. Перенос на другой GPU требует повторных замеров. Порог окупаемости только времени freeze равен `t_freeze / (t_reference − t_export)`, если знаменатель положителен.

Происхождение учебного скрипта — процедуры `MLIP-research/scripts/hpc/inference-benchmark-worker.py` и `scripts/assess_inference_benchmark.py`. Здесь выделены захват предсказаний и численная проверка. Демонстрация работает на искусственных числах. Полноценное сравнение требует собственного checkpoint, рабочей версии DeepMD/PyTorch/ASE и целевого оборудования. [Действующий навык экспорта](../../skills/mlip-deployment/SKILL.md).
